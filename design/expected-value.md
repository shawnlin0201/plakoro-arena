# 期望值怎麼算

招式期望值的計算規則，以及**每一種效果各自用什麼方式換算成數字**。

實作在 `src/game/moveExpectedValue.js`（逐招）、`src/game/tempoValue.js`（節奏計價）、
`src/game/characterRanking.js`（強度排行）。
**這份文件記錄的是每種效果為什麼這樣定價、以及背後的取捨**，不是程式碼的翻譯。
改了效果的語意就回來更新這裡。

手冊〈特殊增益效果〉那章的底稿也在這裡。寫給讀者時可以略過「不可知」那幾類，
但**第六節的重複計算規則一定要寫進去**——那是讀者最容易算錯的地方。

---

## 一、期望值是什麼

**一次施放造成的 HP 淨變化**，站在使用者的立場：

```
期望值 = 傷害 － 自傷 ＋ 減傷 ＋ 回血 ＋ 節奏
         evDamage  evSelf  evDefensive  evHeal  evTempo
```

五個分量相加剛好等於總期望值，所以可以當成總值的拆解來看，不是五個互不相關的統計量。

幾個刻意的決定：

- **不算弱點加成。** 計算器沒有對手可查屬性。這個問題問的是「用我這副骰子，哪一招划算」，
  而一個會落在「剛好對到弱點」那招上的固定加值不會改變答案。
- **減傷預設不計入，由呼叫端決定**（`countDefensiveValue`）。少挨 20 點等於多 20 HP，
  前提是對手本來真的打得到 20。
- **回血有上限，減傷沒有。** 回滿血的招在滿血時值 0，在殘血時值很多，所以回血一定要知道
  現在血量。同一次施放裡的多段回血**共用同一個缺口**——上半段先回掉的，角色骰那段就回不到了。

---

## 二、兩層機率

每一招都要過兩關，兩者相乘：

| | 是什麼 | 怎麼算 |
|---|---|---|
| **能量骰** | 付不付得出需求能量 | 窮舉這副骰子所有擲出結果，數有幾種付得出來 |
| **角色骰** | 效果那一面有沒有出現 | 覆蓋幾面就是幾/6 |

角色骰的六面會被招式的效果條目切乾淨（每張印出來的卡，各條目的骰面都不重疊），
所以**一個條目就是一個分支**，剩下沒被認領的面就是「什麼都沒觸發」那支。

期望值 = 能量付得出的機率 × Σ(各分支權重 × 該分支的淨值)

> **為什麼期望值對角色骰命中率是線性的**
> 上面那條式子裡，分支權重是唯一跟角色骰有關的東西，淨值不隨機率變。
> 所以只要算出「一定中」和「一定不中」兩個端點，中間任何命中率都能直接內插：
> `EV(p) = p × EV(一定中) + (1−p) × EV(不中)`。
> 重擲的計價、角色骰固定朝下的計算，全都靠這條性質，不必另外寫引擎。

## 三、四種計價方式

43 種效果型別分成四類：

| 類別 | 怎麼變成數字 | 標記 |
|---|---|---|
| **直接 HP** | 效果本身就是 HP，直接加減 | — |
| **條件式** | 先判斷前提成不成立，成立才計入 | `needsHp` / `needsPrev` |
| **節奏計價** | 不動 HP，改變雙方能做什麼——查節奏表換算成 HP | `tempo` |
| **不可知** | 取決於對手的卡，這裡查不到 | `unknown` / `mirrorDice` |

沒有處理常式的型別會標 `unsupported` 而不是悄悄算 0，
這樣 `npm run fetch-data` 抓進來的新卡會浮出來，不會默默歪掉數字。

## 四、節奏表：把「不能做事」換算成 HP

斷對手一顆骰值多少 HP？沒有共同單位就沒辦法跟傷害相加。節奏表就是那張匯率表。

做法是：**拿一副牌組，比較「有那顆骰」和「沒那顆骰」時，它最好的打法差多少期望值。**
差額就是那顆骰的價錢。牌組取前 4 招，打法取其中最強兩招的平均
（`sustainableValue`——只看最強一招會高估，因為你不可能每回合都付得出它的能量）。

### 兩張表，不要混用

| | 對手表 `tempoValues` | 自己表 `selfTempoValues` |
|---|---|---|
| 拿誰算 | 環境中最強 5 隻的平均 | **當下這隻角色，用當下這副骰子** |
| 用在 | 打在對手身上的效果 | 打在自己身上的效果 |
| 為什麼 | 你不知道會遇到誰，取強者當基準 | 這沒有未知數，是確切值 |

兩張表差很多。以吉利蛋（主飛副火）為例：

| | 對手表 | 吉利蛋自己 |
|---|---|---|
| 少一顆能量骰 | 11.42 | **3.98** |
| 角色骰被禁用 | 10.21 | **1.53** |

吉利蛋主力招 2 飛就付得出來，少一顆照樣打；環境前五強靠大招吃飯，斷一顆骰就廢掉半回合。
**自己少一顆骰絕對不該用對手的價錢來罰。**

> 這是實際發生過的錯誤：火焰放射的逆面是「下回合自己少擲一顆骰」，
> 舊版用對手表罰了 11.42，實際只值 3.98，整招被低估 0.3。

### 對手表現值（2026-10，會隨卡池變動）

| 項目 | 值 | 意思 |
|---|---|---|
| `base` | 34.38 | 完整狀態下一回合的價值 |
| `denyDice1` / `denyDice2` | 11.42 / 28.12 | 少 1 / 2 顆能量骰 |
| `denyCharaDie` | 10.21 | 角色骰被禁用 |
| `denyDice2AndChara` | 29.71 | 兩者一起 |
| `nullifyDamage` | 25.99 | 傷害完全無效化 |
| `bindMove` | 3.72 | 封住一招 |
| `gainDice1` / `gainDice2` | 9.35 / 12.97 | 多 1 / 2 顆能量骰 |

**封招只值 3.72**，因為封掉最強的一招，對手還有第二強的可以打，差距沒有想像中大。
減骰貴得多，因為那是全面降級。

## 五、逐效果對照

### 直接 HP

| 效果型別 | 算法 | 例 |
|---|---|---|
| `DAMAGE_EXTRA` | 直接加傷害。負值就是減傷害 | 角撞 |
| `DAMAGE_SELF` | 直接扣自己。負值是回血 | 突擊 |
| `DAMAGE_MULTIPLY` | 把當下累積的傷害乘上去 | 反射屏障 |
| `HEAL_SELF` | 回血，上限是「現在缺多少」 | 生蛋、吸取之吻 |
| `HEAL_SELF_FULL` | 回滿＝回「已失去的血量」。**不知道血量就算 0 並標記** | 生蛋（立面） |
| `MOD_REDUCE_TAKEN` | 減傷，`countDefensiveValue` 開了才計入 | 忍耐 |
| `NULLIFY_TAKEN_LE` | 擋住 N 以下的攻擊。沒有對手可問，**credit 上限值** | 鋼鐵身軀 |
| `DAMAGE_EXTRA_ENE` | 計算付款時擲出的該屬性能量數 × 值 | 烈焰風暴 |
| `DAMAGE_EXTRA_ENE_<屬性>` | 同上，但數的是指定屬性（不是招式自己的屬性） | 龍之爆發數雷 |

`DAMAGE_EXTRA_ENE` 的平均數是**在付得出來的那些擲出結果裡**取的，不是全部結果——
付不出來的那些根本不會施放，不該拉低平均。

### 角色骰機率型

| 效果型別 | 算法 |
|---|---|
| `DAMAGE_EXTRA_<N>CHARADICE` | 招式自己擲 N 次角色骰。這顆骰不歸玩家支配，所以**沒有「沒觸發」分支**，期望＝N × (命中面/6) × 值 |
| `DAMAGE_EXTRA_CHARADICE_REPEAT` | 中了就加值再擲，直到沒中。成功次數是幾何分布，E[n] = 1/(1−p) |
| `DAMAGE_EXTRA_CHARADICE_ENEMY_<面>` | 看**對手**的角色骰。機率照樣是面數/6 |
| `DAMAGE_EXTRA_CHARADICE_3COMBO_ENEMY_<面>` | 同上但擲 3 次 |
| `SPECIAL_REPEAT` | 中了就整招重打一次（能量也重擲）。解成不動點：總值 = 單次值 × 1/(1−q) |

### 條件式

| 效果型別 | 前提 | 不成立時 |
|---|---|---|
| `DAMAGE_EXTRA_<N>HP_LOW` | 自己血量 ≤ N | 不計入 |
| `MOD_REDUCE_TAKEN_<N>HP_LOW` | 同上 | 不計入 |
| `DAMAGE_EXTRA_IF_UNHURT` | 上回合沒受傷 | 不計入 |
| `DAMAGE_EXTRA_DICE_MISS_ENEMY` | 上回合對手施放失敗 | 不計入 |
| `DAMAGE_EXTRA_DICE_MISS_SELF` | 上回合自己施放失敗 | 不計入 |
| `DAMAGE_EXTRA_DICE_SUCCESS_SELF_<卡號>` | 上回合成功放了指定招 | 不計入 |
| `DAMAGE_SELF_DICE_SUCCESS_SELF_<卡號>` | 同上 | 不計入 |

這些前提由呼叫端設定（期望值計算參數面板）。**不論成不成立都會標記**，
因為那個數字只在該前提下成立。

### 節奏計價

| 效果型別 | 查哪張表 |
|---|---|
| `MOD_DICE_ENEMY` | 對手 `denyDice1` / `denyDice2` |
| `MOD_CHARADICE_ENEMY` | 對手 `denyCharaDie` |
| `MOD_DICE-CHARADICE_ENEMY` | 對手 `denyDice2AndChara` |
| `MOD_NULLIFY_TAKEN` | 對手 `nullifyDamage` |
| `SPECIAL_BIND_WAZA` | 對手 `bindMove` |
| `SPECIAL_PICK_ENEMY_WAZA` | 對手 `bindMove`（見下） |
| `REROLL_DICE_ENEMY` | 對手 `denyDice1` / `denyDice2` |
| `MOD_DICE_STEAL` | 對手 `denyDice1` ＋ 自己 `gainDice1` |
| **`MOD_DICE_SELF`** | **自己** `gainDice1/2`（加骰）或 **負的** `denyDice1/2`（減骰） |
| **`REROLL_CHARADICE_SELF`** | **自己** `rerollCharaDie1/2`（見第六節） |
| `FIX_CHARADICE*` | 表裡沒有這項，是已知的 0 |
| `SPECIAL_SWAP_CHIP` | 同上，已知的 0 |
| `MOD_NULLIFY_TAKEN_IF_ENEMY_CHARADICE_<面>` | 對手 `nullifyDamage` |

`SPECIAL_PICK_ENEMY_WAZA`（指定對手要打哪招）其實比封招強——封掉最強的，對手還有第二強；
指定的話對手只剩最爛的。但目前用同一個 `bindMove` 定價，**這是刻意的低估**：
旁邊有節奏標記的低估，好過憑空發明一個倍率。

### 不可知

| 效果型別 | 為什麼 |
|---|---|
| `DAMAGE_BY_ENEMY_3DICE` | 要對手擲骰。退而求其次：假設對手骰子跟我們一樣，標 `mirrorDice` |
| `DAMAGE_COPY_LAST` | 複製對手上一招印的傷害，那張卡這裡看不到 |
| `DAMAGE_EXTRA_VS_TYPE_<屬性>` | 取決於對手屬性 |
| `SPECIAL_IGNORE_WEAKNESS` | 弱點本來就不在模型裡，無視它等於預設行為 |

## 六、特殊增益的計價原理

這一節是手冊那章的重點。三個增益長得像，計價邏輯完全不同。

### 「禁用」量的是換招的損失

`denyCharaDie` 問的是：骰子沒了，你最好的打法差多少。答案通常是「改用不吃那顆骰的招」。
所以它量到的是**替代成本**，不是那顆骰在單一招式上的貢獻。

吉利蛋就是典型例子。逐招看，角色骰在每一招上都很值錢：

| 招式 | 有角色骰 | 禁角色骰 | 差 |
|---|---|---|---|
| 生蛋 | 28.6 | 19.1 | +9.5 |
| 滾滾攻擊 | 22.7 | 16.0 | +6.7 |
| 拍打 | 16.6 | 10.0 | +6.6 |
| 拍擊 | 25.4 | 19.1 | +6.4 |
| 捨身撞擊 | 25.5 | 20.4 | +5.1 |
| 幸運拳 | 24.1 | 24.0 | +0.1 |

但 `denyCharaDie` 只有 **1.53**——因為骰子被禁時你改打幸運拳就好，而幸運拳剛好是全隊
唯一不吃角色骰的招。**量「沒了還剩什麼」會被那個「剩下的」決定**，這是這個指標的本質，
不是 bug，但讀的時候要知道它在答什麼問題。

### 「重擲」量的是命中率提升

重擲不是禁用的反面。禁用是你得換招，重擲是**你照樣打同一招，只是命中率變高**。

玩家只有在當下這面不如其他還可能擲到的面時才會重擲，所以最終結果等於
「擲 r+1 次裡最好的那一面」。把分支按價值由高到低排，累積機率 C，第 i 支的權重是：

```
weight_i = (1 − C_{i−1})^(r+1) − (1 − C_i)^(r+1)
```

單一觸發面（覆蓋 k 面）的命中率就化簡成 `1 − (1 − k/6)^(r+1)`：

| 重擲次數 | 單面命中率 |
|---|---|
| 0 | 16.67% |
| 1 | 30.56% |
| 2 | 42.13% |

所以重擲的價錢**必須回頭看自己最強那幾招**，不能用骰子單價除一除。
吉利蛋實測：重擲 1 次 **4.71**、2 次 **8.68**。

> 舊版用 `denyCharaDie ÷ 2 = 0.76` 粗估，把機會擲骰從 24.9 壓到 20.0。
> 全卡池只有機會擲骰和幸運拳吃這個效果，兩張都是吉利蛋的。

### 「減骰」是唯一會算出負值的

`MOD_DICE_SELF` 值為負時代表自己下回合少擲一顆，記成 **負的 `denyDice1`**。
全卡池 16 筆，正負都有。**一定要用自己表**，理由見第四節。

## 七、不能重複計算

> 這是讀者最容易算錯的地方，手冊那章務必寫清楚。

增益的價值**記在發動它的那一招上**，不記在後面受惠的那一招上。

機會擲骰的 24.9 裡面，19.1 是它自己打出的傷害，**5.87 是「下回合那招會更準」的預付**。
而表上其他招（拍擊 25.4、捨身撞擊 25.5）印的都是**沒有重擲**的基準值。

所以兩回合連打的總值是：

```
✅ 機會擲骰 24.9 ＋ 拍擊 25.4（基準值）
❌ 機會擲骰 24.9 ＋ 拍擊 30.7（已含重擲）  ← 重複算了
```

記在哪一邊都可以，**但只能記一邊**。引擎一律記在發動者身上，手冊的招式表也是基準值，
兩邊一致。

**例外是血量註表。** 生蛋那張「重擲 0 / 1 / 2 次」的表，列的是**已經含重擲**的生蛋，
那是第二種記法。那張表的數字不可以再加上機會擲骰的期望值。

同樣的道理適用於所有節奏效果：打在對手身上的減骰、封招，價值都記在造成它的那一招，
對手下回合那些被削弱的招，表上印的仍是完整狀態的數字。

## 八、已知限制

| 限制 | 影響 | 現況 |
|---|---|---|
| 自己表選牌組時不知道血量 | `HEAL_SELF_FULL` 算 0，**生蛋排第 7 進不了前 4 牌組**，吉利蛋的重擲價值仍被低估 | 未修。修了會讓重擲價值變成血量的函數 |
| `SPECIAL_PICK_ENEMY_WAZA` 用 `bindMove` 定價 | 低估 | 刻意，見第五節 |
| `FIX_CHARADICE*`、`SPECIAL_SWAP_CHIP` 無計價 | 算 0 | 表裡沒有對應項目 |
| 不算弱點 | — | 刻意，見第一節 |
| `NULLIFY_TAKEN_LE` credit 上限值 | 高估 | 沒有對手可問 |
| 節奏表隨卡池浮動 | 改一張卡的能量會動到前五強，連帶動到所有章節的期望值 | **資料先定稿，再一次重算全書** |
