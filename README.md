# PLAKORO ARENA
遊玩網址：https://shawnlin0201.github.io/plakoro-arena/dist/
支援版本：預組 01-09，探險隊 01。（共 15 隻寶可夢、126 個招式）

# 目前功能主要包含了
- 雙人對戰：基本上與 PLAKORO 原先規則相同，主要是用來輔助玩家對戰遊玩
- 單人爬塔：享受基於 PLAKORO 規則所改編的 Rougelike 遊戲，至少需要一組預組才能遊玩
- 模擬組骰：離線試組能量骰，可 3D 擲骰、比較兩組骰子、查看能量組合機率與各招式成功率
- 店家資訊：查看店家地圖、賽事行事曆與店家清單

# 單人爬塔
> 『踏上 PLAKORO 的冠軍之路！』你將在旅途中遇到其他訓練家，從戰鬥中逐步累積經驗並強化 PLAKORO 的能力，打敗三大天王贏得 PLAKORO 冠軍！

## 與 PLAKORO 不同的是
- 初始狀態只擁有一顆能量骰子與兩樣招式
- 招式學習耗能不超過當下骰子數量 * 2
- 電腦執行招式：替電腦丟角色骰+關卡數量的骰子（ex: 第一關只丟一個），並只看能量數量不看能量顏色。

## 在戰鬥過程中你可能會遇到
- 戰鬥：與其他電腦訓練家對戰並獲得經驗值。
- 事件：各種與寶可夢相遇的事件，有機會強化你的 PLAKORO
- 篝火：回血回血！休息是為了走更長遠的路。

## PLAKORO 成長方式
戰鬥：過程中累積經驗值後可以從攻擊/防禦/HP 上限擇一增加
打敗天王：獲得新的招式

## 無法出招時
爬塔起手只有兩招，可能遇到「一招被對手封印、另一招是上回合剛用過」而無招可出的情況（招式滿四招時不會發生）。此時招式面板會出現「跳過這回合」按鈕，跳過後下一回合即恢復可用。電腦遇到相同狀況時也會跳過該回合。

# 模擬組骰
> 離線試組屬於自己的能量骰，測試不同搭配下的擲骰結果與機率分布。

## 能量骰構造
一顆完整能量骰由兩個半顆組成：
- 2 面固定類型（無法更改）：凸面固定為草/火/水/雷/鋼其中一種，凹面固定為惡/鬥/超/飛其中一種
- 2 個圓槔：插單能量晶片（任意一種類型）
- 2 個方形槔：插雙能量晶片（可選兩種類型，斜線分半，也可以相同）

## 組骰功能
- 點擊任一面即可開啟能量選擇視窗調整該面能量
- 骰子2、骰子3可勾選「與骰1相同」，之後骰子1的任何調整都會即時同步過去
- 快速套用純屬骰：一鍵把圓槔、方槔（含凸面或凹面，依所選能量所屬固定池而定）全部換成單一屬性
- 新增一組骰子來比較：可再開一組「骰組 B」（建立時複製骰組 A），之後機率表與招式機率都會並列顯示兩組數字，用來比較「改一個面差多少」

## 模擬擲骰
- 3D 擲骰：真實物理模擬（Three.js + cannon-es）的擲骰台，按住畫面聚攏骰子、拖曳搖晃、放開擲出，由骰子實際落地的面決定結果
- 快速擲骰：略過動畫直接取得結果

## 結果機率表
整理三顆骰子一起擲的 216 種面組合，依「最終集齊的能量組合」統計機率並降序排列。
- 只看：複選特定能量來篩選組合
- 依數量排序：把相同能量數量的組合分組彙總（可收合展開查看細項）
- 顯示累計機率／顯示恰好機率：在分組模式下切換。「恰好 N 個」是剛好擲出該數量的機率，「N 個以上」是累計機率（例如招式需要 3 個火，能付得起的是「3 個以上」而不只是剛好 3 個）
- 顯示次數：勾選後除了百分比也顯示 `n/216` 的次數

## 招式機率
選一隻寶可夢，列出牠**所有**招式在目前骰子配置下的成功率（能湊出招式所需能量的機率）。
- 「無色」需求可由任何能量支付，其他屬性則必須由該屬性支付
- 參與擲骰：可個別設定每顆骰要擲幾次（有些規則允許同一顆骰擲多次），機率會依總擲骰次數重算
- 角色骰效果標示於卡片下方，顯示的是**累進機率** —— 招式要先成功才會進行角色骰判定，所以是兩者的聯合機率（例如招式 80%、角色骰 3/6，實際發動為 40%）
- 有骰組 B 時，每個招式都會並列顯示兩組的機率

# 店家資訊
- 地圖：可遊玩／販售店家的 Google 我的地圖
- 行事曆：賽事與活動行程
- 店家清單：從 Google 試算表讀取，可依「類型」標籤複選篩選（多選為 AND 條件）

# 開發
```bash
npm install
npm run dev          # 開發伺服器
npm run build        # 建置到 dist/
npm run fetch-data   # 從 Supabase 重新抓取角色與招式資料到 src/data/generated/
```

多語系（日／英／繁中）：介面文字在 `src/i18n/locales/`，寶可夢與招式名稱的翻譯在 `src/data/translations/`（以日文為基底，缺少翻譯時自動顯示日文原文）。

資料庫的部分欄位含有多餘空白（例如招式 `STW05-002` 的 id 尾端有換行字元），且無權限在 Supabase 端修正，因此 `useCharacterData.js` 於讀取時會自動修剪所有用於比對與查找的欄位（id、角色名），重新執行 `fetch-data` 也不會受影響。

*部分功能與資料 fork 自 beymetchannel/PlakoroBattle，特此感謝 beymetchannel 開源

- 資料已支援雙弱點（`weakness_type2`），但資料庫目前所有寶可夢皆只有單一弱點，尚未有實際案例可驗證
